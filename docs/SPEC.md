# NeatFeed 产品规格 v0.3

> 工作名 `NeatFeed`（采石场：持续开采、堆积、随时取用），包名与中文名待定，见第 14 节。
> **v0.2 变更**：采集与库提前成为 v1 的唯一产物；选题流与提问整体后移到 v1.5（设计不变，实现推后）。
> **v0.3 变更**：确立「传输 × 抽取 × 计划」的统一采集抽象（平台只是配方）；条目契约定为四段 + 两条时间；标签归一与媒体策略进入 v1；UX 承诺改成三个可测数字。
> 仓库：https://github.com/Qiuses/neatfeed（2026-11-09 创建，公开）
> 本文是动工前的唯一依据。改产品先改这份文件，再改代码。

## 0. 三句话

**产品的一句话**：把你关注的互联网，变成一个能随时提问的库。

**v1 的一句话**：把你关注的站点，攒成一个能翻、能搜、能信、能带走的资料库。

**v1 不是什么**：不是半个成品。它完成的是"库"这一层，不是"先搭个架子以后再补"。选题流与提问在 v1 里**不存在**（不是灰掉的按钮）——灰按钮等于自曝半成品。

三条不可妥协：

1. **可读优先于可采。** 库必须是能翻能搜的界面；"采进去了但看不见"不算完成。
2. **每一条都可回溯。** 任意条目都能看到来源、原始 URL、抓取时间、采集链。
3. **凭据不进插件。** 插件永不直接读取 cookie 库、Keychain、浏览器密码存储；登录态只存在于浏览器 profile 内部，插件通过 CDP 发指令。

## 1. 用户与场景

**第一用户**：内容 / 自媒体从业者（选题、对标、行业动态），一个人写稿，每天要决定"今天写什么"。

v1 只覆盖"找素材"这一段，但这三个时刻必须赢：

| 时刻 | 用户动作 | v1 要给的东西 | 失败长什么样 |
|---|---|---|---|
| 上午 10:30 | 想写某话题，先翻库 | 搜关键词 → 3 秒内看到 20 条相关材料，带来源和时间 | 搜不到，或搜出一堆重复 |
| 下午 1:00 | 挑素材 | 详情抽屉：正文、媒体、作者、互动量、原始链接 | 点进去只有标题和一个坏链接 |
| 下午 3:00 | 写稿 | 选中 8 条 → 导出 Markdown/CSV，带引用编号 | 只能一条条复制粘贴 |

**v1.5 才有的两个时刻**（现在不做，但 schema 必须能承接）：早上 9:00 看选题流；上午 11:00 问一句话出一份梳理。

**他们的现状**：浏览器开 30 个标签页、微信收藏夹堆满、笔记软件存了链接从不回看、选题靠刷热搜凭感觉。

## 2. 产品结构

### v1：三页，第一屏 = 库

```
NeatFeed
├── 库（默认，第一屏）
│   ├── 列：时间 / 来源 / 一句话标题 / 标签 / 格式 / 状态（作者·互动量按源可选）
│   ├── 搜索（全文）+ 筛选（来源·时间·标签·格式）+ 存为视图
│   ├── 批量选择 → [导出] [标记] [删除]
│   └── 详情抽屉：正文、媒体、原始字段、采集链、[打开原页]
├── 采集
│   └── 源卡片：平台徽标 · 目标 · 频率 · 上次运行 · 状态灯 · 条数 · 失败率
│       └── [测试] [单次] [计划] [登录] [日志] [改]
└── 设置
    └── 模型 / 浏览器 / 存储 / 频率与礼貌 / 隐私
```

### v1.5 追加（已设计，不实现）

选题流（成为新第一屏）· 提问（库内检索 + 覆盖度 + 成文）· Word 简报 · 小红书适配 · 多库 · 对标账号面板 · 导出到 Obsidian。

**引导流程**（首启，三步，可跳过）：

1. **选源**：平台模板（知乎 / B站 / 微博 / 公众号直链 / 通用网页 / RSS），填账号或关键词。预填 3 个示例，可直接下一步。
2. **连浏览器**（可选，可后置）：点"打开采集浏览器" → 启动专用 Chrome → 扫码登录 → 检测登录态 → 完成。
3. **跑首轮**：立刻采集，实时流式显示 `正在抓 知乎 · 已入库 23 条`，抓完直接进库。

> 第 3 步必须让用户在 3 分钟内看到**真数据**。看不到真数据的引导页，等于没有引导页。
> 第 2 步允许跳过：不连浏览器也能用 RSS + 通用网页跑起来，能力打折但不阻塞。

## 3. 核心流程

### 3.1 采集（v1 实现）

**总纲：一种抽象，不是一堆 RSS 适配器。** 市面上的采集方式看着五花八门，拆开只有三个变量：

```
源 = 传输（怎么把字节拿回来）× 抽取（怎么变条目）× 计划（什么时候跑）
```

| 变量 | 取值 | 说明 |
|---|---|---|
| 传输 | `feed` · `http` · `api` · `browser` · `manual` | browser 走 CDP（含登录态）；manual 是贴一条 URL |
| 抽取 | `feed` 解析 · `selectors` · `jsonPath` · `readability` 正文 · `platform` 配方 | 平台配方 = 预填的抽取 + 常见失败应对 |
| 计划 | 单次 · 循环 · 定时 · 链式（采集完成后触发） | 落 `next_run_at`，重启不丢 |

**平台不是代码分支，是配方。** 知乎、微博、B站、小红书、公众号、YouTube 都只是「预填好三个变量的一张配置」。加一个新平台 = 加一份配方，不改条目模型、不改库、不改 UI。

**v1 只开四个入口**（架构留全，界面不膨胀）：

| 入口 | v1 | 说明 |
|---|---|---|
| 贴一条 URL | ✅ | 单条收录，最高频，也最容易被低估 |
| RSS / OPML 导入 | ✅ | 迁移既有订阅，是我们少数能赢的地方 |
| 网页列表（选择器 / 自动识别） | ✅ | 通用网页的主力 |
| 平台配方（知乎 · B站 · 微博） | ✅ | 预填配方 |
| JSON 接口 | ⏳ v1.5 | 抽象同源，只是还没界面 |
| 站内搜索（关键词订阅） | ⏳ v1.5 | |
| 推送（webhook / 邮件转存） | ⏳ v1.5 | |
| 浏览器历史 / 书签导入 | ❌ | 隐私风险太高 |

**「能容纳所有采集方式」成立的前提是上面这张表**：新增方式 = 新增一个传输或抽取器，条目模型与库完全不动。反过来，如果每种方式都变成一条独立流水线，维护成本会随方式数量线性上涨——这是 v1 之后最容易踩的坑（见第 13 节）。

**礼貌与风控**（写进代码，不是文档）：

- 同域最小间隔 3s + 抖动；单源日上限（默认 300 条）；夜间降频。
- 公开页遵守 robots；登录页只做"以用户身份正常浏览"，不做"绕过"。
- 出现验证码 / 风控页 → 立刻停该源、标红、不重试轰炸。
- 单次运行上限：20 分钟 / 200 次请求，超时即止并记账。

### 3.2 选题（v1.5，设计定稿）

```
候选 = 近 24–48h 入库条目
粗筛（规则，零成本）：跨源共振 + 互动量分位 + 增速 + 新词
  → 每领域前 40 条
精排（模型）：打分 + 一句"为什么值得写" + 建议角度
  → 前 8–10 条落 topic 表（当天固定，不随刷新变动）
```

规则层必须可解释（卡片上写"3 个源都在说 / 互动量前 5% / 2 小时内出现"）；模型只排序、只写理由，**不负责发现事实**。模型不可用 → 纯规则降级，功能不挂。

### 3.3 提问（v1.5，设计定稿）

```
question
  → 查询改写（关键词 + 时间范围 + 实体）
  → 库内检索（FTS5 + 元数据过滤）→ 候选 30–80 条
  → 覆盖度评估：条数 / 时间跨度 / 来源数 / 是否含一手源
  → 足够   → 综合成文，每条论断挂 citation
  → 不足   → 停下来，说清缺什么，给两个按钮：
              [就现有材料写，标注证据不足]  [现在去抓（限定 N 个站）]
  → 现抓：只抓与问题相关的 3–5 个站点/页面，入库后继续
```

覆盖度声明是产品的一部分：

> 基于库内 **37 条**相关材料，时间 2026-10-12 ~ 2026-11-08，来源 6 个（一手源 2 个）。
> 缺少：官方公告原文。建议补抓 36kr / 知乎。

### 3.4 交付（Markdown 进 v1，Word 进 v1.5）

- **v1**：Markdown / CSV / JSON 导出，带引用编号与出处表。
- **v1.5**：Word 简报（标题页 + 目录 + 结论 + 分节 + 出处表 + 附录片段）。
- 两种都要能被 `[3]` 回溯到库内条目 → 原始 URL + 抓取时间。

## 4. 功能范围

### v1（唯一产物：可读的库）

| # | 功能 | 说明 |
|---|---|---|
| 1 | 引导三步 | 含跳过、含首轮实时流 |
| 2 | 采集入口（4 个） | 贴 URL / RSS+OPML / 网页列表 / 平台配方（知乎·B站·微博）；JSON·站内搜索·推送留 v1.5 |
| 3 | 统一采集抽象 | 传输 × 抽取 × 计划 三变量；加平台 = 加配方，不改条目模型 |
| 4 | 浏览器采集 | 专用 Chrome profile + CDP，登录一次长期有效 |
| 5 | 库表格 + 详情抽屉 | 列可配、10k 条流畅 |
| 6 | 搜索 + 筛选 + 存视图 | FTS5 全文 + 元数据过滤 |
| 7 | 导出 | Markdown（含出处表）/ CSV / JSON |
| 8 | 库健康度 | 每源：条数、失败率、重复率、字段完整度 |
| 9 | 运行台账 | 每次采集可查、可忽略、失败可诊断 |
| 10 | Agent 检索工具 | 给 DSH 主 agent 暴露 `neatfeed_search`：**只返回条目，不做综述** |

### v1.5

库内问答（综合 + 覆盖度 + 现在去抓）· 选题流 · Word 简报 · 小红书适配 · 多库 · 对标账号面板 · 导出到 Obsidian

### 明确不做（v1 与 v1.5 都不做）

- 不做通用搜索引擎替代
- 不做点赞/评论/发帖/私信等**任何写操作**
- 不做自动发布到公众号/小红书（要发就导出）
- 不做云同步、多用户、团队协作
- 不做移动端
- 不做向量数据库（先 FTS5 + 模型重排；10 万条以内够用）
- 不做付费/授权

## 5. 平台可行性（实话）

| 平台 | 取数方式 | 登录 | 难度 | 风险 | v1 |
|---|---|---|---|---|---|
| RSS / 通用网页 | HTTP + 抽取 | 无 | 低 | 反爬、改版 | ✅ |
| 知乎 | 登录后 web 页 | 需要 | 中 | 验证码、限流 | ✅ |
| B站 | 公开 API/页面 | 部分 | 低 | 低 | ✅ |
| 微博 | 登录后 web | 需要 | 中高 | 风控严、易限流 | ✅ 低频只读 |
| 公众号 | 需公众号后台扫码登录（第三方 runtime）或文章直链 | 需要 | 高 | 要背 Python 常驻服务；搜狗限流 | ⚠️ v1 只做直链 + RSS |
| 小红书 | 登录 + 强签名 | 需要 | 极高 | 反爬极强、易封号 | ⏳ v1.5 |
| 抖音 | 登录 + 签名 | 需要 | 极高 | 同上 | ❌ |

**公众号（修正）**：微信没给读者端提供网页登录，但**公众号后台可以扫码登录**，已有插件（`dsh-wechat-collector`）用这条路做到采集，代价是背一个 Python runtime + launchd 常驻服务。所以公众号不是「不可能」，是「v1 不值得」——等库跑起来再评估，别在描述里承诺。

**封号风险**：以用户身份高频访问，被限制的可能是**用户自己的账号**，不是插件。所以频率保守、默认低频、首次风险确认，永远先跑公开页。

## 6. 条目契约与数据模型

### 6.1 一条条目 = 四段 + 两条时间

界面上的卡片、表格行、详情抽屉、导出文件，都只用这四段，不多不少：

| # | 段 | 字段 | 谁产生 | v1 规则 |
|---|---|---|---|---|
| 1 | **一句话标题** | `title` | 模型优先；无模型退化为正文首句 | ≤40 字；原文标题留在 `origin_title` 可切换；同源连续 3 条标题雷同 → 标 `suspect` |
| 2 | **标签** | `tags[]` → `tag_id` | 模型 2–4 个；无模型时取原文标签 / 来源名 | 必须归一（见 6.2） |
| 3 | **内容** | `text` + `media[]` | 抽取器 | 正文纯文本 + 媒体清单；HTML 仅在该条含媒体时保留 |
| 4 | **来源说明** | `source_note` | 系统 | 来源名 · 采集方式 · 原始 URL · 原始标题 · 抓取时间（见 6.3） |

**两条时间必须分开存。** 混在一起会让「新内容」判断全错：

- `published_at` — 原文发布时间（可能缺失，缺失即 `null`，不拿抓取时间顶替）
- `fetched_at` — 抓取时间（必有）
- `state` ∈ `normal / duplicate / suspect / error`

表格列 = 四段 + 时间 + 状态。作者、互动量是**按源可选**的附加列，不是每条都有。

### 6.2 标签必须归一，否则半年后作废

标签是库最主要的检索入口，也是最容易失控的字段：同义词（AI / 人工智能 / AIGC）、大小写、长尾（平均每个标签只挂 1.2 条）。

- 写入前归一：去空格、统一大小写、同义词表映射
- 每个标签存 `tag_id` + `canonical` + `aliases[]`
- 标签总数超过 200 后，界面只展示「用过 ≥3 次」的，长尾收进「更多」
- 支持手动合并（把「AI」和「人工智能」并成一个），合并要能撤回

### 6.3 来源说明是一条链，不是一行字

`source_note` 至少四段：**来源名**（知乎 · 某账号 / RSS · 某站）· **采集方式**（feed / http / browser）· **原始 URL** · **原始标题**，外加抓取时间。

这条链是「可回溯」真正落地的地方，也是用户判断某条能不能引用的唯一依据。它必须出现在详情抽屉和导出文件里，不能只躺在数据库里。

### 6.4 媒体策略（别让库变成硬盘杀手）

| 类型 | v1 策略 | 理由 |
|---|---|---|
| 图片 | 存 URL + 只缓存封面/首图（≤2 张/条） | 列表要缩略图，正文图按需 |
| 视频 | 只存 URL + 元数据（平台/时长/封面） | 文件太大且会失效 |
| 附件 | 只存 URL + 文件名/大小 | 同上 |
| 正文 HTML | 仅在该条含媒体时保留 | 否则只存纯文本 |

坏链：条目的媒体 URL 每 30 天抽查一次，失效标 `dead`，界面显示「图片已失效」而不是空白块。

### 6.5 表结构

```sql
source(id, name, platform, transport, extractor, target, config_json,
       schedule, enabled, health, last_run_at, next_run_at)

item(id, source_id, url, url_key, title, origin_title,
     text, html, media_json, metrics_json, source_note,
     published_at, fetched_at, lang, content_hash, state)

tag(id, canonical, aliases_json)
item_tag(item_id, tag_id)

run(id, source_id, started_at, ended_at, status, fetched, inserted, skipped, error_code, snapshot)
view(id, page, name, filter_json, columns_json)
export(id, kind, item_ids_json, path, created_at)

-- v1.5 预留：建空表，不写入
topic(id, day, title, score, reasons_json, item_ids_json, status)
research(id, question, plan_json, coverage_json, item_ids_json, status, created_at)
doc(id, research_id, format, path, citations_json, created_at)
```

约定：`url_key` = 规范化 URL（去 utm、去锚点）；`content_hash` = 正文 simhash；`metrics_json` 至少含 `{views, likes, comments, shares}`，拿不到写 `null`——**不做假 0**（假 0 会让以后的选题算法全部错判）。

## 7. 技术架构

**双半边插件**：

```
package.json
  dsh: { bundle: { patch: "./cordis.patch.yml" }, client: { platform: "web" } }

lib/index.js   宿主：开库、迁移、调度、适配器、抽取、CDP 管理、路由、agent 工具
lib/client.js  浏览器：sidebar.panellist 一行 + main 面板（iframe → /neatfeed）
lib/adapters/  rss.js · http.js · browser.js · platform/{zhihu,bilibili,weibo}.js
lib/extract/   readability.js · normalize.js · media.js · dedupe.js
lib/deliver/   markdown.js · csv.js · json.js
cordis.patch.yml
```

| 关注点 | 选型 | 理由 |
|---|---|---|
| 存储 | `node:sqlite`（Node 24 内置）+ FTS5 | 零依赖，装得快 |
| 正文抽取 | `@mozilla/readability` + `linkedom`，turndown 转 md | 成熟、轻 |
| 浏览器 | `puppeteer-core` + 系统 Chrome/Edge，`userDataDir` 指向 DSH 数据目录 | 不下载 Chromium，市场友好 |
| 调度 | 宿主内定时器 + `next_run_at` 落库 | 重启不丢计划 |
| 模型 | v1 几乎不用；默认走 DSH 宿主模型，可选用户 key | v1 对模型依赖极低，装完就能用 |
| 前端 | 面板 iframe、零构建（原生 JS + SSR 片段） | 改版成本低 |

**动工第一天的两个 spike**：① 宿主侧拿模型能力的正确方式（v1.5 才强依赖，但先确认）；② agent 工具注册方式。

## 8. 安全与信任

插件能驱动浏览器里的登录态，是市场里最高风险品类。设计上让"不信任"没有必要：

| 原则 | 落地 |
|---|---|
| 凭据不进插件 | 不读 cookie 库/Keychain；凭据只在 Chrome profile 内；插件仅 CDP 发指令 |
| 域名可见 | 每次采集列出访问过的域；支持白名单，白名单外的域直接拒 |
| 只读 | 不点赞、不评论、不发帖；表单只用于站内搜索 |
| 本地 | 只存本地 SQLite；无遥测；无云端 |
| 可停 | 每源可暂停；一键清空某源；"紧急停止"立刻断 CDP |
| 开源 | MIT，全源码公开 |
| 诚实 | README 明写"会以你的身份访问这些站，频率受控，但平台风控可能影响你的账号" |

市场自动扫能力标签，红线是"读凭据/密钥 + 有网络访问"。这套设计的目标是扫描结果里**没有 `credentials`**——不是绕过检查，是真不读。

## 9. v1 产物定义（"库做完了"长什么样）

库必须支持四个动作，缺一个都不算完成：

| 动作 | 验收方式 |
|---|---|
| **翻** | 打开就是表格，滚到底不卡，列能配，默认按时间倒序 |
| **找** | 输入一个词，300ms 出结果；能按来源/时间/互动量收窄；筛选可存成视图 |
| **信** | 任何一条都能看到来源、原始 URL、抓取时间；点开能到原页 |
| **带走** | 选中若干条 → 导出 Markdown/CSV，引用编号可回溯 |

外加一条状态可见：采集页一眼能看出"哪个源在正常工作、哪个坏了"。

## 10. 验收标准（可测，不可吹）

| # | 标准 |
|---|---|
| 1 | 新机安装 → 引导 → 3 分钟内第一屏出现 ≥30 条真实条目 |
| 2 | 杀掉进程重启：源计划、库、视图全在，错过的运行下次启动补跑 |
| 3 | 库 10,000 条：滚动不掉帧，搜索 <300ms，筛选 <200ms |
| 4 | 连续跑 7 天：不崩、不漏源、重复率 <0.5% |
| 5 | 字段完整度：标题/时间/正文/URL ≥95%；互动量（支持的平台）≥90% |
| 6 | 每条都能回到原始 URL 与抓取时间，坏链占比 <2% |
| 7 | 导出 Markdown/CSV/JSON 可读、编号可回溯 |
| 8 | 代码无 cookie/Keychain 读取；能力扫描不含 `credentials` |
| 9 | `dsh plugin add` 一次装成，无 postinstall，装完 <30s |
| 10 | 断网 24h 后恢复：退避生效不雪崩，台账可读 |
| 11 | **首条时间**：装好到看见第一条真实条目 ≤ 3 分钟 |
| 12 | **单条收录**：贴一条 URL 到出现在库里 ≤ 20 秒（浏览器路径 ≤ 60 秒） |
| 13 | **标签归一**：200 条样本里同义标签合并率 ≥ 90%；标签总数 ≤ 条目数的 1.5 倍 |
| 14 | **坏链可见**：失效媒体显示「已失效」，不出现空白块 |

## 11. 里程碑（估算，非承诺）

| 阶段 | 内容 | 估算 |
|---|---|---|
| M0 | 骨架：能装、能开面板、SQLite、一个 RSS 源跑通 | 3 天 |
| M1 | HTTP/RSS 采集 + 抽取 + 表格库 + 抽屉 + 搜索 | 1 周 |

| — | **自用版（约 3.5 周）** | |

| M5 | 市场首发（描述只写库，不提提问） | 3 天 |

**为什么先做库**：数据有时效性，功能没有。晚两周写选题流不损失什么；晚两周开抓，库就少两周厚度，而这份厚度任何代码都补不回来。

**Check-point（M2 结束）**：连续 7 天里，你找素材时先打开这个库、而不是先开浏览器标签页 → 继续；否则停下重想。

## 12. 市场发布清单（已核实）

**提交方式**：向 `awesome-dsh-plugin/awesome-dsh-plugin` 提 PR，新增**一个文件**：

```yaml
# data/plugins/<你的GitHub用户名>__quarry.yml
url: https://github.com/<owner>/neatfeed      # 必须与仓库完全一致
name: <owner>/neatfeed
category: browser                            # 合法值之一，browser 最贴切
description:
  en: 'A local library for creators: crawls the sites you follow, extracts the articles, and gives you a table you can search, filter and export.'
  zh: '面向创作者的本地资料库：把你关注的站点持续抓进库里，表格可翻、全文可搜、一键导出。'
icon: https://raw.githubusercontent.com/<owner>/neatfeed/main/assets/icon-180.png
```

> ⚠️ **描述必须与当前版本一致。** 审核会逐条对着源码核；v1 没有提问与选题流，描述里一个字都不能提，否则会被打回，理由通常是"描述超出了实现"。

**硬性要求**：

- [ ] `package.json` 有 `dsh.bundle.patch`（只写 `dsh.client` 会被拒，最常见死因）
- [ ] 仓库根有 `cordis.patch.yml`：`- insert: [{ id: neatfeed, name: <包名> }]`
- [ ] 仓库创建满 **1 天** → **先建仓库再开发**
- [ ] 真实可用代码，非占位
- [ ] `icon`：GitHub 托管位图，方形约 96px，SVG/第三方图床会被拒
- [ ] `screenshots.json` 放 `package.json` 旁，1–8 张仓库内相对路径（推送即生效，无需 PR）
- [ ] MIT + `repository` 字段 + README 双语（英文必备）
- [ ] 无 postinstall（否则被标 `runs code at install time`）
- [ ] 分类 `browser`；同一 PR 最多 3 条

**发布前自检**：找个人只看市场卡片一句话，问"这是干嘛的"，答对了才算合格。

## 13. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| **采集器收集癖**：每个平台都想要，v1 永远发不出 | 烂尾 | v1 死守 6 类模板；新平台必须有人证明需要 |
| **库没有"啊哈时刻"**：翻库是体力活，不如刷热搜爽 | 自用也懒得开 | 靠"能带走"（导出）+ 检索工具 + 健康度撑价值；选题流 v1.5 补爽点 |
| **市场第一印象 = RSS 阅读器** | 没人装 | 卡片与截图只讲"你自己的资料库"，不讲"抓取"；强调可搜可导出 |
| 公众号/小红书抓不动 | 卖点缩水 | 不承诺；v1 靠知乎/B站/微博+RSS 撑住；小红书标 v1.5 |
| 平台风控封用户账号 | 一星 + 口碑塌 | 默认低频、日上限、验证码即停、首次风险告知 |
| CDP 被 Chrome 版本变更打断 | 浏览器采集整体失效 | 版本探测 + 降级 HTTP + UI 明示 |
| 先做库，发布时"没有 AI 感" | 市场里像工具不像智能插件 | 接受。v1 卖"库"，v1.5 卖"提问"；两个版本各讲一件事 |
| **采集方式膨胀**：每种新方式都带新失败模式 | 维护成本随方式数线性上涨，最终没人敢改 | 抽象边界只到「传输 / 抽取」，平台是配方；每加一种方式先证明有 3 个真实用户在要 |
| **标签长尾失控** | 半年后筛不动，库退化成「一堆条目」 | 归一 + 阈值展示 + 手动合并，v1 就要做，不能留到以后 |
| **媒体烂链 / 硬盘杀手** | 体验崩，用户以为插件坏了 | 只存 URL + 封面缓存 + 坏链标记 |
| 与 sel-feed 自我竞争 | 精力分散 | sel-feed 是流水线，NeatFeed 是库；不再给 sel-feed 加同类功能 |

## 15. 术语表（黑话翻译）

规格里出现的所有技术词，一句话解释。看不懂时查这里，不要跳过。

| 词 | 大白话 |
|---|---|
| **URL** | 网址。浏览器地址栏里那一串 |
| **RSS / Atom** | 网站主动提供的一份「新文章清单」，机器能直接读，不用抓网页 |
| **OPML** | 订阅清单的导出文件（`.opml`）。换工具时用它一键搬走所有订阅 |
| **抓取 / 采集** | 让程序代替你打开网页，把内容抄下来存进库 |
| **选择器（selectors）** | 告诉程序「标题在哪个位置、正文在哪个位置」的定位规则 |
| **正文抽取（readability）** | 从广告、导航、评论里自动挑出真正的正文 |
| **无头浏览器（headless）** | 有浏览器内核、但没有可见窗口，适合后台跑 |
| **CDP** | Chrome 的远程控制接口。插件通过它指挥一个真实浏览器（能带登录态） |
| **登录态 / cookie** | 你在浏览器里「已登录」的身份凭证。插件不碰它，只让浏览器自己去用 |
| **FTS5** | SQLite 自带的全文搜索，像书后面的索引，比 `LIKE %关键词%` 快几个数量级 |
| **content_hash / simhash** | 把正文算成一串指纹。两篇指纹几乎一样 = 同一篇，用来去重 |
| **去重** | 同一篇文章被几个源同时抓到，库里只留一条 |
| **台账（run）** | 每次采集的记录：什么时候跑、抓了几条、失败在哪 |
| **来源说明（source_note）** | 这条从哪来、用什么方式抓的、原始地址、原始标题 |
| **归一（标签）** | 把「AI / 人工智能 / AIGC」合成同一个标签，否则筛不动 |
| **模型精排** | 先按规则粗筛，再让 AI 给候选打分排序（只排序，不编事实） |
| **token** | 模型按字数计费的单位，用来算一次调用花了多少钱 |
